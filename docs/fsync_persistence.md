# fsync 的持久化层次与掉电保护

## 问题：fsync 刷新到哪个层次？掉电后保证写入是谁负责？SSD 备用电池的作用？

### fsync 的刷新层次

fsync() 的数据流经过多个层次：

```
fsync() 系统调用
    ↓
内核文件系统层（ext4/xfs 等）
    ↓
块设备层（block layer / I/O scheduler）
    ↓
磁盘/SSD 控制器
    ↓
存储介质（磁盘盘片 / NAND 闪存）
```

**fsync() 保证到哪个层次？**

- **fsync() 保证**：数据已从内核的 page cache 传递到存储设备
- **不保证**：数据已经写入到物理介质（磁盘盘片或 NAND 闪存）
- 实际写入到物理介质由存储设备控制器负责

### 存储设备的掉电保护机制

#### 1. 企业级 SSD（有 PLP）

**PLP (Power Loss Protection)** 掉电保护：

- **硬件实现**：板载钽电容或小型电池
- **容量**：通常能供电几毫秒到几秒
- **作用**：
  - 在掉电时完成正在进行的写入操作
  - 将 DRAM 缓存中的数据刷入 NAND 闪存
  - 保护映射表（FTL）的完整性
- **保证**：掉电后数据不会丢失，映射表保持一致

#### 2. 消费级 SSD（通常无 PLP）

- **无备用电容/电池**
- **依赖软件保护**：
  - 文件系统日志（journaling）
  - 写时复制（COW，如 btrfs、ZFS）
  - 应用层的 fsync/fdatasync
- **风险**：
  - 掉电时 DRAM 缓存数据可能丢失
  - 可能导致数据不一致或文件系统损坏

#### 3. 机械硬盘（HDD）

- **有少量电容**：用于完成磁头归位（parking）
- **不保证写入完成**：掉电时正在写入的数据可能丢失
- **依赖文件系统**：日志机制保证一致性

### 掉电后数据保证的责任层次

| 层次 | 负责内容 | 掉电保护 |
|------|---------|---------|
| 应用层 | 调用 fsync() | 无 |
| 文件系统 | 日志、COW | 软件保护 |
| 块设备层 | I/O 调度、队列 | 无 |
| SSD 控制器 | FTL、DRAM 缓存 | PLP（仅企业级） |
| NAND 闪存 | 物理存储 | 非易失 |

### fsync 的实际保证

**fsync() 的语义**：
- 数据已从内核传递到存储设备
- 存储设备已确认接收（ACK）
- 但不保证数据已写入物理介质

**对于有 PLP 的 SSD**：
- fsync() 后掉电，数据基本安全
- PLP 完成剩余的物理写入

**对于无 PLP 的 SSD/HDD**：
- fsync() 后掉电，数据可能丢失
- 依赖文件系统日志恢复

### 最佳实践

1. **关键数据**：
   - 使用 fsync() 确保数据传递到设备
   - 选择有 PLP 的企业级 SSD
   - 使用支持日志的文件系统（ext4、XFS）

2. **非关键数据**：
   - 可以依赖内核的异步刷新
   - 使用 fdatasync() 提高性能

3. **极端可靠性要求**：
   - 使用 O_DIRECT + fsync()
   - 考虑双写、RAID
   - 使用 UPS（不间断电源）

### 总结

- **fsync()**：保证数据到达存储设备控制器
- **物理写入**：由存储设备控制器完成
- **掉电保护**：
  - 企业级 SSD：PLP（电容/电池）保证完成写入
  - 消费级 SSD：依赖文件系统软件保护
  - HDD：依赖文件系统，无硬件保护
- **SSD 备用电池**：主要用于 PLP，完成掉电时的写入操作和映射表保护
